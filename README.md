# AstrBot Scheduled Check-In Plugin

![AstrBot Plugin](https://img.shields.io/badge/AstrBot-Plugin-blue)
![Vanilla JS](https://img.shields.io/badge/Frontend-Vanilla%20JS%20(0KB%20Ext)-green)
![Framework](https://img.shields.io/badge/Support-New--API%20%7C%20One--API%20%7C%20REST-orange)

自动定时签到各种 LLM API 中转站（如 New-API、One-API 等）的 AstrBot 插件。配备基于 Vanilla JS 的轻量级 Pages 可视化管理面板，支持多凭据管理、Github / LinuxDO OAuth 自动登录、签到日历与余额变化、实时连通性测试、定时/区间随机打卡、代理跳转，以及可选的 AES-256-GCM 配置加密与通行密钥解锁。

---

## 🌟 特性亮点

- **⚡ 原生 Vanilla JS 可视化 Dashboard**
  - **零外部依赖**（0 KB 依赖，不加载 Vue/React、FontAwesome 或远程 CDN），页面加载极其迅速。
  - 内置符合 AstrBot 主题风的 UI 样式与自定义 Modal/Toast 交互，完美适配 iframe 沙盒环境。

- **⏰ 智能定时与区间随机打卡**
  - 支持固定时间打卡，或在设定时间区间（如 `08:00` - `10:30`）内生成随机触发时刻。
  - **智能时区/过期校验**：若重设的时间区间在当天已过，自动识别跳过；若设在当前时间内部，自动在剩余时间内随机分配。

- **🔄 避免重复打卡（今日打卡跳过）**
  - 自动记录各站点当天的打卡状态与时间。对于今天已成功打卡的站点，触发时自动跳过 HTTP 请求，防止重复签到被限制。

- **🛠️ 凭据列表与自定义签到 / 余额配置**
  - 每个站点可维护一份 **凭据列表**：`Authorization Token`（可勾选自动补全 `Bearer`）、`Cookie`、`Github OAuth`、`LinuxDO OAuth`。
  - 站点编辑弹窗按 **`基本 / 凭据 / 签到 / 余额`** 分页签组织，签到与余额各自独立配置 Path、协议、凭据、请求头与 WAF 解算开关。
  - **Path 与协议留空即跟随框架**：New-API 自动使用 `/api/user/checkin`（回退 `/api/user/pay/checkin`）与 `/api/user/self`；通用 REST 站点签到直接 GET 访问 Base URL，余额则不查询。
  - 未指定凭据时按固定优先级自动选择：请求类优先 `Authorization Token`、其次 `Cookie`；OAuth 类优先 `Github`、其次 `LinuxDO`。
  - 内置动态 **Key-Value 编辑器** 可为两个动作分别自定义任意 Header。New-API 站点在「跟随框架」模式下会自动探测 `new-api-user` 并回写到对应配置中。

- **🔐 Github / LinuxDO OAuth 自动登录（含"登录即签到"站点）**
  - 填入第三方站点的**完整 Cookie** 后，插件自动完成 `/api/status` → `/api/oauth/state` → 第三方授权 → `/api/oauth/{provider}` 全流程。
    - Github 需要 `user_session`、`__Host-user_session_same_site`、`_gh_sess`、`logged_in`——**只填 `user_session` 会被 Github 重定向到登录页**。
    - LinuxDO 需要 `_t`、`_forum_session`。
    - `state` 接口自动适配：先试 `GET /api/oauth/state`（经典 one-api），再试 `POST`（较新分支）；
      两者都不存在时改用本地生成的 state。
    - 站点通常把 state 存在**服务端会话**里，插件会把该接口下发的会话 Cookie 一并带到回调，
      否则站点会以 `state is empty or not same` 拒绝。
    - 凭据支持「分项填写」与「完整粘贴」两种输入方式，后者可直接粘贴 DevTools 的
      「Copy as cURL」命令，插件会自动提取其中的 Cookie。
  - 换取到的站点会话 Cookie 回写到该 OAuth 凭据内部，不会覆盖用户手填的 Cookie 凭据。
  - **签到协议选择 `OAuth（重新登录签到）`** 时，视"重新登录"本身为签到动作：部分站点二次开发后关闭了通用签到端点，只有重新登录才会发放额度。此时插件每次签到都会重新走一次完整 OAuth 登录，**不会**复用已保存的会话；余额查询仍复用会话，不会消耗当日签到。
  - 其余协议下会话过期（401/403）时自动重新登录一次并重试。

- **🌐 站点级全局代理 (Proxy)**
  - **自动继承 AstrBot / 系统代理**（`trust_env=True`），轻松请求境外中转站。
  - 单站代理**对该站点全局生效**，包括 OAuth 登录访问的 Github / LinuxDO 等第三方域名。

- **🔒 AES-256-GCM 配置加密（可选）**
  - 在「全局设置 → 配置加密」中开启后，随机生成一个 **仅显示一次** 的密钥，加密范围为**凭据、自定义请求头与代理地址**。
  - 密钥不落盘，每次重载插件后配置处于**锁定**状态，需在 Web 端输入密钥解锁；锁定期间站点列表仍可查看，敏感字段显示为锁定，编辑/测试/签到按钮禁用。
  - 锁定时定时任务照常触发但会**跳过所有站点**并在历史日志中留下说明，不会静默失败。
  - 锁定状态下保存站点不会破坏读不到的密文；密钥丢失可通过「我忘了 Key」二次确认重置——清空密文并关闭加密，站点名称、Base URL、路径配置与历史日志保留。

- **🔑 多密钥槽位 + 通行密钥解锁（WebAuthn PRF）**
  - 数据由一个随机 **Vault Key (DEK)** 加密，每个**槽位**各自封装一份 DEK 副本；**持有任意一个槽位的密钥即可解密**。
  - 统一支持 **Windows Hello、macOS Touch ID / Passkey、Android / iPhone Passkey、YubiKey 及其他 FIDO2 安全密钥**——
    它们在 WebAuthn 层是同一套 PRF 接口，无需分别适配。
  - DEK 仅驻留内存，槽位表中只存封装后的密文（无对应密钥即无意义），**服务器不长期持有任何可解密的密钥**。
  - 「用户密钥」槽位不可删除，作为恢复入口：即使丢失所有设备，仍可用启用加密时保存的 Base64 密钥解锁。

- **🛡️ 精准 WAF 拦截与备用探测**
  - 能精准识别阿里云 ESA / Tengine 等 WAF 返回的 HTML 验证页（`acw_sc`），杜绝"200 OK 假成功"误报。
  - 管理接口被拦截时，会自动尝试探测 `/v1/models` 模型接口，明确区分"API Key 有效"与"WAF 拦截"。

- **🖥️ 浏览器指纹请求**
  - 网络请求使用 `curl_cffi>=0.14.0,<1.0.0`，可在 Web「全局设置」中选择当前库支持的指纹，默认使用 `chrome131`。

- **🧩 可选 acw_sc__v2 纯 Python 解算 (Beta)**
  - 在签到 / 余额配置中分别勾选 **`解算 acw_sc__v2 (Beta)`** 后，可把响应中的 JavaScript 重排与 XOR 算法转换成 Python 代码并自动重试原请求。
  - 转换结果按算法指纹缓存，动态 `arg1` 变化不会重复写入；仅在重排表或 XOR 密钥变化时新增缓存。
  - 运行时不依赖浏览器、Node.js 或远程 JavaScript 执行服务。

- **📜 日志明细与抽屉面板**
  - 支持侧边抽屉拉出查看，内置**滚动自动下滑翻页**加载更多历史记录，精准区分 `单站连通性测试`、`手动一键签到` 与 `自动定时签到`。
  - 每条结果附带**请求链路追踪**（步骤、方法、URL、状态码与响应摘要），失败时无需重跑即可定位原因；
    URL 会去掉查询串，响应与追踪长度均有上限，不会让日志无限膨胀。
  - 全局设置支持按**保留天数**和**保留条数**独立清理日志；任一项设为 `0` 表示该条件不限制，两项都设置时同时生效；
    `auto_cleanup_logs` 是总开关，关闭后两条规则都不生效。

- **📅 签到日历与余额变化**
  - 点击站点的**今日签到状态**即可查看月度签到日历、当前余额与余额变化记录，可按月份前后翻页。
  - 仅对 `New-API` / `One-API` 展示余额；这两类站点会在签到前后查询余额并计算本次签到增量，其他站点不显示余额字段。
  - 连通性测试不计入签到天数，但其余额会纳入余额变化曲线。
  - 日历只读取历史日志与 `last_quota`，**锁定加密时依然可以查看**。

## 🖥️ Pages Dashboard 使用方法

1. 在 AstrBot 管理后台中进入 **插件管理** 页面；
2. 找到 `astrbot_plugin_scheduled_check_in` 插件；
3. 点击 **「管理面板」** 按钮，即可直接打开可视化 Dashboard 进行中转站配置维护、一键打卡与日志查看。

### 新增站点

1. 点击 **新增中转站**，在 **基本** 页填写站点名称、框架类型、Base URL，按需填写站点代理；
2. 切到 **凭据** 页，添加至少一个凭据。使用 OAuth 时填入对应第三方域名的会话 Cookie；
3. **签到** / **余额** 页留空即可跟随框架，需要时再自定义 Path、协议、凭据与请求头；
4. 保存后可点 **测试** 校验连通性（该操作只查询状态，不会触发签到或 OAuth 登录）。

### 关闭了签到端点的站点（登录即签到）

若站点提示类似「需要退出后重新登陆才会到账」，说明其通用签到端点已被关闭：

1. 在 **凭据** 页添加 `Github OAuth` 或 `LinuxDO OAuth` 凭据，填入第三方域名的会话 Cookie；
2. 在 **签到** 页把协议改为 **`OAuth（重新登录签到）`**，Path 留空；
3. 之后每次签到都会重新登录一次，**并且不再请求任何签到端点**——登录本身就是签到，
   登录后用新会话 Cookie 查询余额；额度变化会作为 `额度增加 +$ N` 记入简报，
   否则记为「OAuth 重新登录成功（登录即签到）」。

> **凭据 Cookie 会自动跟随轮换。** Github / LinuxDO 在使用过程中会轮换会话 Cookie，
> 浏览器之所以能保持登录，正是因为它持续保存轮换后的值。插件同样会从授权响应中取回
> 被轮换的 Cookie 并写回该凭据（只替换已持有的项，不会新增或清空），登录失败时也会写回——
> 站点可能在拒绝前就已更换会话，继续重放旧值只会保证下一次也失败。
> 在编辑弹窗中未改动的 OAuth Cookie 保存时会被跳过，因此期间发生的轮换不会被覆盖回旧值。

> **Github 凭据仍可能失效。** Github 会对请求环境做检测，服务端发起的授权请求与该 Cookie
> 原本所属的浏览器特征不一致，可能触发风控使 Cookie 失效，**有时会连带注销你在浏览器里的
> github.com 登录**。表现为签到日志中「Github OAuth 授权」一步返回 302 跳转到
> `github.com/login`。此时需要重新复制完整 Cookie；若反复失效，建议改用 `LinuxDO OAuth`
> 或普通的 `Token` / `Cookie` 凭据。这是 Github 侧的策略，插件无法规避。

### 获取 new-api-user

New-API 用 `new-api-user` 请求头把 Cookie 会话绑定到数字账号 ID。在 **签到** / **余额** 页的
「自定义请求头」旁点 **获取 new-api-user**，插件会通过 `/api/user/self` 读取并填入下方，随站点配置一起保存。

- 仅 New-API 有此字段，其他框架下该按钮自动隐藏。
- One-API 没有该字段，探测失败时会明确提示「可能是 One-API（不需要 new-api-user）」，不会改动已有请求头。
- 该操作只读，不会触发签到，也不会消耗 OAuth 站点的当日登录。

> 第三方授权页需要用户**至少在浏览器中授权过该站点的 OAuth 应用一次**，否则第三方会返回授权确认页而非授权码，插件会明确提示这一点。

### 启用配置加密

1. 打开 **全局设置**，在底部 **配置加密** 中打开开关并确认；
2. 弹窗会显示一次性密钥，**请立即保存**；
3. 之后每次重载插件，先在顶部横幅点击 **输入密钥解锁** 才能编辑、测试或签到。

## 🔑 通行密钥（Passkey / 安全密钥）

### 密钥槽位模型

```
Vault Key (DEK)  ── 加密凭据 / 自定义请求头 / 代理地址
  ├── 用户密钥槽位      密钥 = 启用加密时保存的 Base64 密钥（不可删除，恢复入口）
  ├── 通行密钥槽位      密钥 = WebAuthn PRF 输出   ← Windows Hello
  ├── 通行密钥槽位      密钥 = WebAuthn PRF 输出   ← Touch ID / iPhone Passkey
  └── 通行密钥槽位      ...                        ← YubiKey 等 FIDO2 安全密钥
```

每个槽位独立封装同一个 DEK：`KEK = HKDF-SHA256(槽位密钥, 槽位盐, 槽位类型)`，
`封装值 = AES-256-GCM(KEK, DEK)`，并把槽位 ID 作为附加认证数据绑定，防止密文在槽位间搬移。
槽位表本身不含机密（封装值没有对应密钥就毫无意义），因此**锁定状态下也能读取**，
这正是解锁流程列出可用凭据所必需的。

### 使用方法

通行密钥的注册与解锁在**独立页面**中完成：

```
http://<你的面板地址>/api/v1/plugins/extensions/astrbot_plugin_scheduled_check_in/passkey
```

在插件面板的「全局设置 → 密钥槽位 → 管理通行密钥」或锁定横幅的「使用通行密钥」中可复制该地址。
该页面与管理面板同源、复用登录状态，无需再次登录。

> **为什么必须新开标签页？** AstrBot 用 `sandbox="allow-scripts allow-forms allow-downloads"`
> 承载插件页面，未包含 `allow-same-origin`，iframe 因此处于**不透明源**，浏览器无法确定 WebAuthn 的
> RP ID，`navigator.credentials` 在其中一定失败。沙箱也未开放 `allow-popups`，
> 所以插件无法代你打开新标签页，只能提供地址。

注册流程：**解锁配置 → 打开该页面 → 注册当前设备 → 完成一次生物识别 / PIN 验证**。
之后锁定时，在该页面点「使用通行密钥解锁」即可。

### 让浏览器密码管理器记住 Base64 密钥

该独立页面提供一个标准密码表单（`autocomplete="current-password"`），
可被浏览器密码管理器自动填充；勾选「成功后询问浏览器是否保存密钥」时会在解锁成功后请求保存。
表单不含账户字段——密码管理器本身按域名区分条目，浏览器也支持只有密码的表单。

- **Chromium（Chrome / Edge）**：通过 `navigator.credentials.store` 直接弹出保存提示。
- **Firefox / Safari**：没有该接口，保存依赖表单提交启发式，本页用 fetch 提交因此不会弹窗——
  自动填充仍然可用，保存需手动添加到密码管理器。页面会如实说明当前浏览器的结果。

> 管理面板的解锁弹窗**无法**接入密码管理器：浏览器要求凭据存取所在文档与其所有祖先同源，
> 而插件页面被沙箱置于不透明源（`window.origin === "null"`），调用会直接抛
> `NotAllowedError`。因此需要密码管理器时请使用独立页面。

### 环境要求（重要）

WebAuthn 要求**安全上下文**，且 RP ID 必须是**域名**：

| 访问地址 | 是否可用 | 说明 |
| :--- | :--- | :--- |
| `http://localhost:6185` / `127.0.0.1` | ✅ | 浏览器视为安全上下文 |
| `https://面板域名` | ✅ | 最推荐，手机 Passkey 与跨设备扫码也可用 |
| `http://192.168.x.x:6185` | ❌ | 既非安全上下文，IP 也不能作为 RP ID |

**反向代理**：RP ID 由页面自身的 `location.hostname` 决定，而不是服务端的 `Host` 头——
否则代理转发到 `127.0.0.1` 时会推断出错误的域名并导致注册被拒。
服务端另外识别 `X-Forwarded-Host` 与 `Forwarded`，两者不一致时页面会提示。

**通行密钥与域名绑定**：在 `localhost` 注册的密钥无法在 `nas.example.com` 使用，反之亦然。
如果你会从多个地址访问，请为每个地址分别注册一个通行密钥（槽位数量不限）。
页面会自动只列出与当前地址匹配的通行密钥，并在不匹配时提示已注册的地址。

此外，PRF（底层为 CTAP2 `hmac-secret`）的实际支持情况取决于**浏览器与认证器的组合**，
差异较大。页面会做能力检测：若认证器不返回 PRF 结果，会明确提示该设备不可用于加密解锁，
并且不会留下半注册的槽位。

### 安全说明

- **删除槽位只阻止它将来解锁**，无法追溯保护它此前已能读取的数据——任何槽位持有者都能解出 DEK。
- 解锁时 PRF 输出会发送到服务端用于解封 DEK（插件需要在服务端发起签到请求），
  用完即弃、不写入磁盘。这与现有 Base64 密钥的传输方式一致；请通过 HTTPS 或 localhost 访问。
- 插件**不验证 WebAuthn 断言签名**，也不需要服务端 WebAuthn 库：PRF 输出本身就是密钥，
  拿不到它就无法通过 GCM 认证，安全性由密码学而非签名校验保证。

## 📂 数据持久化

插件数据存储在 AstrBot 统一的数据目录中：
`data/plugin_data/astrbot_plugin_scheduled_check_in/`

- `data.db`：SQLite 本地数据库（采用 WAL 高并发模式），统一持久化中转站配置（`sites` 表）、全局设置（`settings` 表）、
  密钥槽位（`vault_slots` 表）、历史打卡/测试日志（`history_logs` 表）、日志与站点的关联索引（`history_log_sites` 表，
  供签到日历按站点快速筛选）以及存储层元数据（`storage_metadata` 表，记录一次性索引回填标记）。
- `acw_sc_v2_cache.json`：保存已验证算法转换生成的 Python 源码，仅在启用 Aliyun WAF 解算后按需创建。
- `*.json.bak`：若从旧版升级，初次启动时会自动将历史 JSON 文件导入 SQLite 数据库，并将原文件自动备份为 `.json.bak`。

### 加密字段划分

开启配置加密后，`sites` 表中只有下列字段被加密：`proxy`、`credentials`、`checkin_headers`、`balance_headers`。
签到与余额的 Path、协议、所选凭据 ID 与 WAF 解算开关保持明文，因此锁定状态下站点列表依然可读。
`vault_slots` 表全部为非机密数据（封装后的 DEK、凭据 ID、盐），锁定时可读。
数据密钥（DEK）与用户密钥都**不会写入数据库**，仅保存一个校验块用于验证旧版密钥。

### 从旧版本升级

旧版的单一鉴权字段会在首次启动时自动迁移，无需手动操作：

| 旧字段 | 迁移结果 |
| :--- | :--- |
| `auth_type` + `auth_value` | 合并为凭据列表中的一条 Token / Cookie 凭据（Token 默认开启自动补全 `Bearer`） |
| `checkin_endpoint` | 签到配置的自定义 Path（余额 Path 留空，改为跟随框架） |
| `custom_headers` | **同时**写入签到与余额的自定义请求头 |
| `solve_acw_sc_v2` | **同时**写入签到与余额的解算开关 |
| `proxy` | 保持不变，语义扩展为对该站点全局生效 |

如果你在上一版已启用过配置加密，首次用原密钥解锁时会自动升级为槽位结构：
沿用原密钥作为数据密钥，**已加密字段一个字节都不会改动**，保存的 Base64 密钥永久有效。
升级完成后即可添加通行密钥。

*插件代码更新、重载或重启 Bot 不会丢失用户配置与数据。*
